# V147 — BATTLE 2.0: نبرد واقع‌گرایانه، سخت و عادلانه

مبنای کار: پرامپت مالک «بازطراحی سیستم نبرد و فتح — واقع‌گرایانه، سخت و عادلانه».
قانون طلایی رعایت شد: **منطق بازی و امنیت (آتش‌بس المپیک، داوری سرور PvP، ضدتقلب، سقف ۱۵ کشور) دست‌نخورده** — همه‌چیز داخل همان مسیرها ادغام شد، هیچ wrapper تازه‌ای روی `attackTarget` سوار نشد (از V59 تک‌منبع است) و مسیر PvP همان `pvp_attack` است.

## وضعیت قبلی (از کد، نه حدس)
- **PvE**: دفاع = `t.def×1.42` ثابت؛ ۵ دور؛ فقط مهاجم تلفات می‌داد؛ پادگان نداشت، بازسازی نمی‌شد، ترکیب یگان‌ها بی‌اثر بود.
- **PvP (سرور)**: مهاجم = «امتیاز رتبه‌بندی»، مدافع = «تخمین امتیازِ مدافع» + یک شانس برنولی (`0.5+(a−d)/2(a+d+500)`) — یگان‌های واقعی هیچ نقشی نداشتند.
- **دو باگ واقعی که همین ردیابی کشف کرد و رفع شد**: سپر ۲۴ساعته‌ی V130 فقط کلاینت بود (سرور `p_attack` را نادیده می‌گرفت ⇒ در PvP بی‌اثر)؛ صلح مقدس V98 هرگز از سرور نمی‌آمد (`error:'peace'` هیچ‌وقت تولید نمی‌شد).

## فرمول‌ها (تک‌منبع: `src/lib/battleConfig.ts` ↔ `WD_BATTLE` در index.html)

**پادگان کشور** (PvE کامل، PvP با `ownedK=0.12`):
```
G = def × 1.42 × (1 + 0.18×popN + 0.10×ecoN)      سقف: def×2.2
popN = min(1.4, √popM/√300) · ecoN = min(1.2, log10(1+gold)/log10(1+12000))
```
آمریکا ≈ ۱۷٬۷۴۹ · ایران ≈ ۱۲٬۸۲۰ · ایسلند ≈ ۶۲۰.

**قدرت‌ها (PvP — هر دو از یگان واقعی سیو):**
```
A = min( armyPower(units) × خستگی‌جنگ × RPS(ترکیب مهاجم، ترکیب مدافع), 120 + 2×score )
D = min( armyPower(units_مدافع)×0.55×(1+0.05×استحکامات)×راهبرد×shareEff×(1+0.01×ژنرال‌دفاع) + G×0.12, 120+2×score )
D = max(D, min(score_مدافع, سقف)×0.5)      ← کف میراث: بی‌ارتش بی‌دفاع نمی‌ماند
سپر نوپدید: کشورِ تازه‌تصرف (Territory.updatedAt<24h) ⇒ D×1.8 (این بار سمت سرور)
```

**شبیه‌ساز ۵ دور (یکسان سرور/کلاینت):**
```
defNow = G×(0.35+0.65×HP)×(1−occ/100×0.75)   — از ۷۵٪: ×1.35 (محاصره‌ی پایتخت)
ratio = A×rand(0.9..1.1)/defNow
gain  = clamp(16×(ratio−0.35), −3, capG(ratio))   capG: <4→13% · <8→26% · ≥8→34%
gain ×= 0.45 در محاصره · ×(1−0.15×popN) زمین بزرگ
تلفات مهاجم ≤۱۰٪/دور · فرسایش مدافع = min(30٪, 0.7×تلفات×ratio) → HP پادگان
برد = occ به ۱۰۰ برسد (نه شانس تک‌ضرب) · پیشروی جزئی ذخیره و با فرسایش ۱۵٪/ساعت عقب می‌راند
```

## ادغام‌ها (چه چیزی کجا شد — بدون شکستن ساختار)
- **`attackTarget` (تک‌منبع V59)**: حداقل نیرو (قبل از هر هزینه‌ای)، خستگی جنگ، پادگان HP، RPS، تلفات دوطرفه، محاصره‌ی پایتخت — داخل بدنه، بدون wrapper. هوک‌ها (truce/pvpRoute/cinema/xpPost) دست‌نخورده.
- **`pvp_attack` (سرور)**: همان زنجیره (سقف کشور، دوئر، آتش‌بس، هزینه V75، عملیات‌ها V55، انتقام V34، تاکتیک V65، CV V68، عمق جنگ V88) — فقط موتور قدرت/داوری عوض شد؛ پاسخ قدیمی + فیلدهای تازه (`rounds/atk_loss/def_loss/bully/shielded`).
- **st28 (استحکامات/راهبرد)**: از سیو مدافع خوانده می‌شود (`state.wd28`) — همان UI قبلی، حالا در PvP واقعاً اثر دارد.
- **توزیع پادگان**: دکمه‌ی ± در کشوی کشورِ خودی (`state.gdf`، پیش‌فرض ۵۰٪، سقف ۶۰٪) — سرور در دفاع همان کشور می‌خواند.
- **روزنامه**: اعلان `pvp_incoming` («🚨 دژ … زیر آتش … است») برای مدافع در لحظه‌ی حمله + گزارش تلفات مدافع در پیام نتیجه.
- **تلفات مدافع**: سمت سرور روی سیو مدافع (همان مسیر تک‌نویسنده‌ی tradeApply) با سقف ۳۰٪/۱۲٪ — ارتش باید بازسازی شود.

## چک‌لیست تست دستی (گوشی واقعی + نت ایران)
1. **حمله‌ی ضعیف رد شود**: با ارتش استارتر به ترکیه/ایران بزن → پیام «حداقل قدرت لازم ≈ …» قبل از کسر لجستیک.
2. **حمله‌ی کافی موفق شود**: ارتش ~۲برابر پادگان ایسلند → چند موج، نوار پیشروی بین حمله‌ها حفظ می‌شود، پادگان در کشو کمتر نمایش داده می‌شود (HP).
3. **مدافع آفلاین با یگان واقعی**: دو حساب با امتیاز برابر اما ارتش متفاوت → دفاع دومی به‌مراتب سخت‌تر؛ در روزنامه‌ی مدافع «🚨 دژ …» ظاهر شود.
4. **تقلب از مرورگر**: ویرایش `units` در سیو (DevTools/فیلتر پروکسی) → قدرت از `120+2×score` عبور نمی‌کند؛ حمله‌ی جعلی همان نتیجه‌ی ارتش واقعی است.
5. **محاصره‌ی پایتخت**: از ۷۵٪ آهنگ پیشروی نصف؛ استحکامات/راهبرد «سنگر» مدافع در PvP محسوس.
6. **ضد قلدری**: حمله به امتیاز پایین‌تر از ۱۰۰۰ با قدرت >۴× → +۲۵۰ امتیاز به‌جای +۱۰۰۰.
7. **آتش‌بس/دوئر/سقف ۱۵ کشور**: مثل قبل — هیچ رفتاری عوض نشده باشد.
8. **بازسازی**: ۱ ساعت بعد از حمله‌ی نیمه‌کاره، پادگان ~۱۴٪ برگشته و پیشروی رهاشده ~۱٪ عقب — کمپین باید تمام شود.
