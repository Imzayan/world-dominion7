# 🌍 World Dominion — نسخه آنلاین با سرور و دیتابیس اختصاصی

بازی استراتژیک فتح جهان، حالا **کاملاً آنلاین** با سرور و دیتابیس اختصاصی خودتان — بدون نیاز به Supabase یا هیچ سرویس خارجی دیگر.

## ✨ چه چیزهایی اضافه/اصلاح شد؟

### 🖥️ سرور و دیتابیس اختصاصی (به‌جای Supabase)
- **احراز هویت کامل** (ثبت‌نام/ورود) با نشست امن httpOnly cookie — از هر دستگاهی با همان نام و رمز وارد شوید
- **ذخیره‌سازی ابری پیشرفت بازی** — هر ۸ ثانیه و هنگام خروج، با قفل خوش‌بینانه برای جلوگیری از تداخل دو دستگاه
- **۵ سرور چندنفره** — کشورها به‌صورت first-come-first-served بین بازیکنان تقسیم می‌شوند؛ کشور بازیکنان دیگر روی نقشه با رنگ و اسم دیده می‌شود
- **نبرد PvP زنده** — حمله به کشورهای بازیکنان دیگر با مالکیت سرور-محور (Realtime با SSE + fallback)
- **چت جهانی**، **اخبار جهانی** (فتح کشورها، حملات PvP) و **رتبه‌بندی ۴ دسته‌ای** (کشورگشایی/کشتار/اقتصاد/نیرو)
- **کیف پول جم** با پنل مدیریت برای اهدای منابع توسط مدیر
- تمام APIها روی `/api/*` هستند و دیتابیس Prisma است (SQLite به‌صورت پیش‌فرض، PostgreSQL اختیاری برای Render)

### 🐛 باگ‌های رفع‌شده
1. **حمله‌ها لغو می‌شدند** — چک مالکیت کشور به‌خاطر ناسازگاری شکل داده (`maybeSingle`) همیشه اشتباه جواب می‌داد
2. **سیو بازیابی نمی‌شد** — استیت بازی به‌صورت `[object Object]` ذخیره می‌شد؛ حالا JSONB-semantics کامل است
3. **رنگ کشورها بعد از ریلود** — رِیس کاندیشن در رنگ‌آمیزی قلمروها هنگام ساخت تدریجی نقشه
4. **کشورهای کوچک (جزیره‌ای) محو می‌شدند** — ساده‌سازی هندسه دیگر جزیره‌های ریز را نابود نمی‌کند
5. **چت خودکار رفرش نمی‌شد** — چک کلاس اشتباه (`open` به‌جای `active`)
6. **خطای `W.map.getContainer`** در لایه ارتقای نقشه
7. **ServiceWorker 404** — سرویس‌ورکر واقعی با کش هوشمند (آفلاین‌فرندلی)
8. **پرچم‌ها** — از `/cdn/flags` (۴۰۴) به flagcdn منتقل شدند
9. پیام‌های قدیمی «فایل SQL را اجرا کن» با پیام‌های درست جایگزین شدند
10. عیب‌یاب اتصال حالا سرور واقعی خود بازی را تست می‌کند

### ⚡ رفع لگ
- به‌روزرسانی‌های UI به‌صورت **diff-based** شدند؛ DOM فقط وقتی تغییر کرده عوض می‌شود
- شمارنده‌های منابع دیگر هر تیک بازسازی نمی‌شوند (فقط متن تغییر کرده آپدیت می‌شود)
- کاهش چشمگیر فشار GC و layout thrash

### 🗺️ کیفیت نقشه فوق‌العاده
- **اقیانوس سینمایی** با گرادیان‌های عمق + وینیت سینمایی
- **گراتیکول تاکتیکی** (شبکه جغرافیایی) زیر خشکی‌ها
- **نام فارسی همه کشورها** روی نقشه (بسته به زوم) + دیکشنری کامل ۱۷۰+ کشور
- **هاور درخشان** روی کشورها + حلقه نبض روی کشور انتخابی
- پالت رنگ حرفه‌ای جدید برای کشورها

### 🎮 جذابیت و انیمیشن
- همه دکمه‌ها: **ریپل (موج آب) + فشار + بالا-پریدن هاور** 
- شمارنده منابع هنگام افزایش **پاپ (جهش)** می‌زند
- دکمه مالیات/کمک وقتی آماده است **نبض طلایی** می‌زند؛ آیکن ناوبار هم می‌درخشد
- مودال‌ها با انیمیشن نرم باز می‌شوند
- **سیستم لقب و رتبه** (آغازگر → فرمانده → سردار → فتحگر → امپراتور → فرمانروای زمین) روی HUD
- **تاج 👑** برای نفر اول رتبه‌بندی
- **۴۰ جم خوش‌آمدگانی + ۲۰ جم پاداش ورود روزانه** (خودکار از سرور)
- شمار بازیکنان آنلاینِ سرور روی HUD

## 🚀 استقرار روی Render با GitHub (قدم‌به‌قدم)

### قدم ۱: پروژه را به GitHub ببرید
```bash
git init
git add .
git commit -m "World Dominion online"
git branch -M main
git remote add origin https://github.com/USERNAME/world-dominion.git
git push -u origin main
```

### قدم ۲: ساخت دیتابیس (برای ماندگاری داده‌ها)
1. وارد [dashboard.render.com](https://dashboard.render.com) شوید
2. **New → PostgreSQL** → نام دلخواه (مثلاً `wd-db`) → Create
3. بعد از ساخت، بخش **Connections** → مقدار **Internal Database URL** را کپی کنید

> 💡 اگر دیتابیس نسازید، بازی با SQLite اجرا می‌شود ولی با هر redeploy داده‌ها ریست می‌شوند.

### قدم ۳: ساخت وب‌سرویس
1. **New → Web Service** → مخزن GitHub خود را وصل کنید
2. تنظیمات:

| مورد | مقدار |
|------|-------|
| Runtime | **Node** |
| Build Command | `npm install && npm run build` |
| Start Command | `npm start` |
| Instance Type | Free |

3. بخش **Environment Variables** یک متغیر اضافه کنید:

| Key | Value |
|-----|-------|
| `DATABASE_URL` | (همان Internal Database URL قدم ۲) |
| `NODE_VERSION` | `20` |

4. **Create Web Service** بزنید. تمام! بعد از build، بازی روی آدرس `https://your-app.onrender.com` آنلاین است.

> 🎮 نکته: نام کاربری `Alireza` به‌صورت خودکار دسترسی **مدیر** (پنل 👑 مدیریت) می‌گیرد. برای تغییر، مقدار `ADMIN_NICK` در فایل بازی و `alireza` در `src/app/api/auth/signup/route.ts` و `src/lib/auth.ts` را عوض کنید.

## 🗂️ ساختار پروژه
```
├── prisma/
│   ├── schema.prisma            # اسکیمای دیتابیس (SQLite)
│   └── schema.postgres.prisma   # همان اسکیما برای PostgreSQL
├── public/
│   ├── game/index.html          # بازی کامل (تک‌فایل)
│   ├── sw.js                    # سرویس‌ورکر آفلاین
│   └── cdn/                     # Leaflet، مرز کشورها، شیم سرور
├── src/
│   ├── app/
│   │   ├── api/
│   │   │   ├── auth/            # ثبت‌نام، ورود، خروج، نشست
│   │   │   ├── db/[table]/      # REST سازگار با Supabase
│   │   │   ├── rpc/[fn]/        # توابع سرور بازی (PvP، کیف پول، ...)
│   │   │   └── rt/[ch]/         # Realtime (SSE) برای نبردهای زنده
│   │   └── page.tsx             # ریدایرکت به بازی
│   └── lib/                     # احراز هویت، دیتابیس، Realtime hub
└── scripts/prisma-setup.mjs     # انتخاب خودکار SQLite/PostgreSQL
```

## ❓ سوالات پرتکرار

**بازی بدون دیتابیس Render هم کار می‌کند؟**
بله، با SQLite خودکار اجرا می‌شود؛ فقط با هر deploy داده‌ها صفر می‌شوند. برای ماندگاری، PostgreSQL را وصل کنید.

**بازیکنان چطور حساب بسازند؟**
روی صفحه ورود، «ثبت‌نام» — نام و رمز انتخاب می‌کنند و پیشرفتشان روی سرور ذخیره می‌شود. هر دستگاه فقط یک حساب می‌تواند بسازد (ضد مولتی‌اکانت).

**چطور به بازیکن جم بدهم؟**
با حساب مدیر (Alireza)، دکمه 👑 مدیریت در نوار پایین → انتخاب بازیکن → ارسال طلا/نفت/غذا.
